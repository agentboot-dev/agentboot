# Changelog

All notable changes to AgentBoot are documented here. The format is based on
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project follows
[Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Per-release GitHub Releases (generated by release-drafter from merged PRs) carry the
full PR-level detail; this file is the curated, human-readable summary.

## [Unreleased]

Work on the `release/v0.11` branch toward the v1.0 line.

### Added
- Weight-tier trait sections: a trait may split weight-sensitive guidance into
  `### LOW|MEDIUM|HIGH|MAX` sections and the compiler injects only the tier nearest the
  persona's weight (opt-in; untiered traits compile unchanged), cutting persona token bloat.
- `/ab` status now reports the full artifact inventory (personas, traits, gotchas, lexicons —
  core vs org-specific), not just personas.

### Fixed
- Validation now scans config-referenced domain layers (`domains/*`) — previously a domain's
  broken trait refs, missing SKILL.md frontmatter, or secrets passed validation vacuously.
- `/ab` status / `list_repos` report real drift (content-hash comparison) instead of mere
  manifest existence; a synced repo with modified managed files is now correctly flagged, and
  `lastSyncAt` reads the actual manifest location (`.claude/.agentboot-manifest.json`).
- Gitignore conflict detection is wired into `sync` (per-repo write-time warning) and `doctor`
  (standing check, exit 1) — a managed file a repo's `.gitignore` excludes is no longer synced
  silently (invisible to the team and to drift-check).
- MCP hub resolution surfaces a diagnostic when it falls back to bundled content or when
  `AGENTBOOT_HUB` overrides a differing registry default; package artifact counts are derived
  rather than hardcoded.
- Baseline type safety: resolved two `noPropertyAccessFromIndexSignature` errors and added a
  typecheck step to CI (previously no workflow ran `tsc`).

### Security
- URL import enforces its fetch size cap **during** a streamed read, so a chunked-encoding
  response (no `content-length`) can't buffer an oversized body into memory before the check.
- User-level content delivery refuses files containing unresolved `{{ template vars }}`, which
  would otherwise break a downstream config manager's all-or-nothing template resolution.

### Documentation
- CONTRIBUTING now requires contributors to anonymize employer/org/client content (code, commit
  messages, PR descriptions, fixtures, examples) with a matching PR-checklist item.

## [0.11.0] — 2026-04-26

### Added
- **Phase 11**: OpenAI Codex platform support (`.codex/` config, hooks, skills); governance
  improvements (drift detection, HARD/SOFT guardrails, managed-settings output); a global hub
  registry so `/ab` resolves the hub from any spoke repo; and a security-hardening pass.

## [0.10.3] — 2026-04-14

### Changed
- `/ab`-first developer experience: installer auto-sync, docs rewritten around `/ab`, and a
  website refresh (new hero, dynamic version/stats, real `/ab` interaction examples).

### Fixed
- Removed `context: fork` from the `/ab` skill (output was being swallowed) and repaired test
  failures introduced by the `/ab` skill + MCP injection changes.

## [0.10.1] — 2026-04-12

### Fixed
- `resolveConfigPath` prefers the current working directory over the package root, so running
  from a hub directory resolves that hub's config.

## [0.10.0] — 2026-04-12

### Added
- **Phase 10**: the `/ab` skill (orchestrator + query/diagnose/author/manage specialists) and a
  16-tool MCP server; `compile`/`sync`/`install` distribute the `/ab` skill files and `.mcp.json`;
  Jaccard-based duplicate detection during import surfaces duplicates and promotion candidates.

### Fixed
- Security audit across path traversal, input validation, shell injection, and secret patterns;
  test-isolation crash guards; routing/behavioral-test corrections.
